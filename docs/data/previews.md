# Realtime Preview(直前情報)

締切5分前のスナップショットをデータソース単位で別ファイルに追記したものです(得点率早見は展示データではありませんが、節の進行に伴って値が変わるため同じ「締切直前スナップショット」として扱います)。
データソースを分割することで当日の値の時間変化を保持でき(特に水面気象)、後段の特徴量計算 (`scripts/boatrace/index_features.py`) もこの per-source CSV を直接参照します。

`scripts/preview-realtime.py` が Cloud Run Jobs (`boatrace-487212/asia-northeast1`) で **JST 08:00〜22:59 の 5 分毎** に動作し、各レースの締切5分前のスナップショットを取得します。

## ファイルパス

- `data/previews/tkz/YYYY/MM/DD.csv` — 体重・展示タイム・チルト
- `data/previews/stt/YYYY/MM/DD.csv` — 進入コース・スタート展示
- `data/previews/sui/YYYY/MM/DD.csv` — 水面気象スナップショット
- `data/previews/original_exhibition/YYYY/MM/DD.csv` — オリジナル展示データ
- `data/previews/tokuten_hayami/YYYY/MM/DD.csv` — 得点率早見
- `data/previews/od1/YYYY/MM/DD.csv` — 集計中オッズ(3連複・拡連複・単勝・複勝)
- `data/previews/od2/YYYY/MM/DD.csv` — 集計中オッズ(2連単・2連複)
- `data/previews/od3/YYYY/MM/DD.csv` — 集計中オッズ(3連単)

**URL 例**: https://boatracecsv.github.io/data/previews/tkz/2026/05/03.csv

## 共通カラム(全ファイル先頭6列)

- `レースコード` (`YYYYMMDDjjrr`): Programs / Realtime Preview 等と JOIN 可能な12桁識別子
- `レース日` (`YYYY-MM-DD`)
- `レース場` (`01`〜`24`、2桁ゼロ詰め)
- `レース回` (`01R`〜`12R`)
- `締切時刻` (`HH:MM`、`getHoldingList2` 由来)
- `取得日時` (ISO8601, JST、例 `2026-05-03T20:25:03+09:00`)

## ソース固有カラム

`tkz` — `状態` (常に `1`) + 6艇 × {`体重(kg)`, `体重調整(kg)`, `展示タイム`, `チルト`}。

`stt` — 6艇 × {`コース`, `スタート展示`}。`F` 付き行は負値の ST、`L` 付き行は空欄として格納。

`sui` — `気象観測時刻` (HHMM) + `風速(m)` / `風向` / `波の高さ(cm)` / `天候` / `気温(℃)` / `水温(℃)`。

`original_exhibition` — `計測数` / `計測項目1` / `計測項目2` / `計測項目3` + 6艇 × {`選手名`, `値1`, `値2`, `値3`}。場ごとに項目が異なります(多くは「一周／まわり足／直線」、住之江・尼崎・徳山は2項目、桐生は「半周ラップ／まわり足／直線」)。

`tokuten_hayami` — `ボーダー順位` + `1着点`〜`6着点` + 6艇 × {`級別`, `登録番号`, `選手名`, `得点率`, `順位`, `ボーダー状態`, `早見`, `1着時得点率`, `1着時状態` 〜 `6着時得点率`, `6着時状態`}。詳細は[得点率早見](#得点率早見-tokuten_hayami)を参照。

`od1` — 3連複 20 通り(`3連複_1=2=3` 〜 `3連複_4=5=6`、組番昇順)+ 拡連複 15 通り × {`下限`, `上限`}(`拡連複_1=2_下限` など)+ `単勝_1`〜`単勝_6` + 複勝 6 艇 × {`下限`, `上限`}。

`od2` — 2連単 30 通り(`2連単_1-2` など。1着艇ごとに相手艇昇順)+ 2連複 15 通り(`2連複_1=2` 〜 `2連複_5=6`、組番昇順)。

`od3` — 3連単 120 通り(`3連単_1-2-3` 〜 `3連単_6-5-4`。1着艇 1→6 の順に、2着艇・3着艇を残り艇から昇順で列挙)。

### オッズ(od1 / od2 / od3)の注意点

- 値はボートキャストの「集計中オッズ」(`bc_smt_od*`)のスナップショットで、**確定オッズではありません**。締切 1〜10 分前(通常約 5 分前)に 1 回だけ記録します。締切までの駆け込み投票は反映されないため、確定オッズとは乖離し得ます。
- `0.0` は「その組番にまだ投票がない」ことを意味します(欠損ではありません)。
- 欠場等で発売されない組番も `0.0` になります。

### 得点率早見 (tokuten_hayami)

出典は `race.boatcast.jp` の `hp_txt/{jo}/bc_j_tokuten_hayami_{YYYYMMDD}_{jo}_{rr}.txt` です。
節内の順位争い(準優勝戦への進出ライン)を、当該レースの着順別に示した表です。

- `得点率`: 現在の得点率 = **着順点の平均**(得点の合計 ÷ 出走数)。得点が付かない選手はここに `賞除` / `欠場` / `帰郷` / `追配` の文字列が入ります
- `順位`: その節の全選手中の順位(1 が最上位)
- `ボーダー順位`: 準優進出ラインの人数(例 `18` = 上位18名。準優が2個レースの節は `12`)
- `ボーダー状態`: `00` / `01`。末尾が `1` のとき `順位 <= ボーダー順位`(元データの黄色表示条件)
- `{k}着点`: **このレースの**着順点。予選は `10 / 08 / 06 / 04 / 02 / 01`、準優・特別レース等は 1 点ずつ高い `11 / 09 / 07 / 05 / 03 / 02` になります
- `艇N_{k}着時得点率`: このレースで k 着だった場合の得点率 = `(現在の得点合計 + k着点) ÷ (出走数 + 1)`
- `艇N_{k}着時状態`: 元データの色分けコード。bit1 = ボーダー得点率以上 / bit2 = 次レースの結果次第でボーダー以上の可能性 / bit4 = 当レース終了時点でボーダー以上
- `艇N_早見`: その選手の当日もう1走のレース番号(1走のみなら空)。`race_cards` の `早見` と同義

**予選最終日までしか公開されません。** また、節によっては最初から公開されないことがあります(ボートキャストの SPA は `mu_txt/noScoringRate.json` で対象外の節を持っています)。どちらの場合も行は追記されないため、**当該レースの行が存在しないことが「表なし」を意味します**。

## 取得・スキップルール

- 中止 / 順延 / 途中中止のレースはスキップ
- ソースファイルがまだ公開されていない、または計測中 (`status=0`) / 計測不能 (`status=2`) の場合は **追記せずスキップ**(次回実行で自動再試行)
- `original_exhibition` は `status=1` のみ追記(旧 `data/original_exhibition/` にあった `ステータス` カラムは廃止)
- `tokuten_hayami` も公開済み (`status=1`) のみ追記。予選最終日を過ぎた節・そもそも得点率早見を出さない節では恒久的に行が増えません
- `od1` / `od2` / `od3` も `status=1`(集計中)のみ追記。3ソースは独立に取得・追記されるため、一部のみ先に記録されても次回実行で残りが補完されます
- 同一 `レースコード` は1日1行のみ(per-source dedup)
- スケジュール実行のため、各レースについて取得は1回のみ

> **用途**: 締切直前のコンディション把握、時系列での風・水温の変化分析、リアルタイム予想モデル特徴量。`レースコード` で他の CSV と JOIN 可能
